Capture Methods & Workflow

Reference for capturing snapshots from a running Node.js process.

🌐HTTP Endpoint Method

Add a debug endpoint to your Node.js app that writes a heap snapshot on request.

// In your Express app: import v8 from 'node:v8'; app.get('/debug/heap-snapshot', (req, res) => { const file = v8.writeHeapSnapshot(); res.json({ snapshot: file }); });
Then capture with:
npx heap-analyzer node-snapshot \ --endpoint http://localhost:3000/debug/heap-snapshot
📡PID / Signal Method

Send SIGUSR2 to a running process to trigger a snapshot (no code changes needed).

# Find your Node.js process PID pgrep -f node # Take a snapshot via signal npx heap-analyzer node-snapshot \ --pid 12345
📊Auto-Monitor Mode

Watch a process and automatically snapshot when memory exceeds a threshold.

npx heap-analyzer node-monitor \ --pid 12345 \ --threshold 500 \ --interval 5 \ --webhook-url https://hooks.slack.com/...
🎯Load Test + Snapshots

Generate heap snapshots throughout a load test to find leak patterns under traffic.

npx heap-analyzer node-load-test \ http://localhost:3000/api/endpoint \ --endpoint http://localhost:3000/debug/heap-snapshot \ --concurrency 50 \ --duration 60
🔄Core 3-Snapshot Workflow
1
Baseline Snapshot
App in clean state — captures initial heap footprint
2
Perform Actions
Execute the operations you suspect of causing a leak
3
Target Snapshot
Captures heap after actions — shows memory that grew
4
Wait & GC
Wait 5–10 s for GC to reclaim short-lived objects
5
Final Snapshot
Captures what survived GC — true leak candidates
6
Find Leaks
Run heap-analyzer find-leaks across all 3 snapshots

Command Reference

All heap-analyzer CLI commands with flags and examples.

🔍Snapshot Analysis
▶ analyze — Single snapshot: node counts, type breakdown, heap size
npx heap-analyzer analyze snapshot.heapsnapshot npx heap-analyzer analyze --file snapshot.heapsnapshot
▶ compare — Side-by-side growth between two snapshots
npx heap-analyzer compare before.heapsnapshot after.heapsnapshot
▶ timeline — Sequential trend analysis across a directory
npx heap-analyzer timeline ./snapshots npx heap-analyzer timeline ./snapshots --threshold 15
▶ find-leaks — 3-snapshot memlab leak detection
# 3 explicit files npx heap-analyzer find-leaks \ --baseline baseline.heapsnapshot \ --target target.heapsnapshot \ --final final.heapsnapshot \ --trace-all-objects # Directory with 3+ snapshots npx heap-analyzer find-leaks --snapshot-dir ./snapshots/leak-test/
🧭Object Investigation
▶ investigate — Combined inspect + trace + deep-dive in one command
npx heap-analyzer investigate snapshot.heapsnapshot --object-id @39263
▶ trace — Retainer path for a specific node
npx heap-analyzer trace snapshot.heapsnapshot --node-id 170921
▶ deep-dive — Recursive object hierarchy exploration
npx heap-analyzer deep-dive snapshot.heapsnapshot \ --object-id @1096221 \ --depth 5 \ --max-children 20 \ --output-format json \ --output-file ./analysis/deep-dive.json
🖥️Node.js Monitoring
▶ node-snapshot — Capture snapshot from running process
npx heap-analyzer node-snapshot --endpoint http://localhost:3000/debug/heap-snapshot npx heap-analyzer node-snapshot --pid 12345
▶ node-monitor — Threshold-based auto-snapshot
npx heap-analyzer node-monitor \ --pid 12345 \ --threshold 500 \ --interval 5
▶ node-load-test — Snapshots during load test
npx heap-analyzer node-load-test http://localhost:3000/api/heavy \ --endpoint http://localhost:3000/debug/heap-snapshot \ --concurrency 50 \ --duration 60

Help & Documentation

Quick reference for heap analysis concepts and interpreting results.

📖Key Concepts
🌱
Baseline snapshot — Heap in a clean, known-good state before any suspect operations.
📈
Target snapshot — Heap after performing the operations you want to analyse.
🧹
Final snapshot — Heap after GC has run. Objects still alive here are true leak candidates.
📊
Retainer path — The chain of references keeping a leaked object alive. The root is usually a global or closure.
🚨
Critical event — A snapshot transition where heap grew by more than the configured threshold (default: 10 MB).
✅
Stable trend — Average growth per event is <10% of the threshold. Memory is healthy.
🏷️Severity Levels
info Growth < 50% of threshold. Normal.
warning Growth 50–100% of threshold. Monitor closely.
critical Growth ≥ threshold. Likely a leak site.
📉Memory Trends
✅ stable — Average growth < 10% of threshold per event. Healthy.
📈 growing — Average growth > 10% of threshold per event. Likely leaking.
📉 shrinking — Average growth is negative. GC is reclaiming memory efficiently.
⚡ volatile — High std deviation. Memory spikes and drops; investigate burst allocations.
🔑Filename Convention

heap-analyzer auto-parses structured snapshot filenames:

heap-2025-12-03T19-32-37-260Z-startup.heapsnapshot heap-2025-12-03T19-42-55-976Z-request-start-op-beatHeartbeat_id-vsjvl25n.heapsnapshot └─timestamp──────────────────────┘ └─operation──┘ └─requestId─┘
